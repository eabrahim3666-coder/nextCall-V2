Twilio Business Verification & Client SMS Enablement

What your codebase does for Twilio, why outbound texts are gated, and the exact steps to let your client businesses register and start sending SMS.

Scope: Twilio + Toll-Free Verification (TFV) App: nextCall (Next.js SaaS) Prepared: 1 Oct 2026
Bottom line

Your code is already built to send each client's toll-free registration request (Settings → Business SMS → Submit). What is missing is entirely on the Twilio account side: get your master account business-verified, create an approved ISV Primary Customer Profile in Trust Hub, and set TWILIO_TFV_CUSTOMER_PROFILE_SID (plus TWILIO_WEBHOOK_BASE_URL). After that, each client's submission reviews and approves normally.

1 · What your Twilio setup actually is (as built)

nextCall is a multi-tenant SaaS. You are the Twilio ISV / reseller; every paying business is an end customer. The chain is:

3 · What is blocking you right now

Findings from your code and .env.local:

1No Customer Profile SID configuredBLOCKING

TWILIO_TFV_CUSTOMER_PROFILE_SID is not set. Your code reads it here — and because it is unset, submissions go out without a Customer Profile. That is the single most likely cause of rejections / Twilio error 30494 ("ISV or reseller name must be provided").

// lib/sms-compliance.ts:537-539
...(process.env.TWILIO_TFV_CUSTOMER_PROFILE_SID
  ? { customerProfileSid: process.env.TWILIO_TFV_CUSTOMER_PROFILE_SID }
  : {}),
2Webhook base URL not set explicitlyRECOMMENDED

TWILIO_WEBHOOK_BASE_URL is unset and silently defaults to https://www.getnextcall.com (lib/sms-compliance.ts:40, lib/twilio-provision.ts:10). Fine today, but set it explicitly so staging/prod can never wire webhooks to the wrong host.

3EIN is now required for US businessesVERIFY FORM

Twilio added mandatory Business Registration Number fields. US businesses must supply a valid EIN matching the legal business name; sole proprietors without an EIN may mark it unavailable. Your form already collects registrationNumber + registrationAuthority (EIN) and sends them (buildCreateParams, lines 530-536) — good — but the UI authority list is minimal and country is hard-defaulted to US, so non-US clients cannot register cleanly.

4Master account must be a paid, upgraded accountCHECK

The account must be upgraded (card on file), not trial, with Twilio's own account-level business verification complete.

4 · The exact plan — do these in order

1Verify / complete your Twilio account (one-time)
  • Twilio Console → confirm the account is upgraded (card on file), not trial.
  • Complete Twilio's own account business verification (Console → Account → Business Info / the verification banner).
2Create your approvable Primary Customer Profile (one-time)
  • Console → Trust Hub → Customer Profiles → Create Profile.
  • At "Business Information → Select business identity" choose ISV Reseller or Partner.
  • Fill legal name, address, and a notification email you actually monitor — Twilio emails approval/rejection here.
  • Submit and wait for the profile to show approved.
3Wire the profile into the app

Copy the approved profile SID (BUxxxxxxxx…) and add it to .env.local and your Vercel environment:

TWILIO_TFV_CUSTOMER_PROFILE_SID=BUxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
TWILIO_WEBHOOK_BASE_URL=https://www.getnextcall.com
4Prove the pipeline with ONE client
  • For a test business: open Settings → Business SMS and fill the form — legal name, EIN matching the legal name, website, opt-in proof URL, Privacy & Terms URLs.
  • Submit, then watch Console → Trust Hub → Registrations (or Phone Numbers → the toll-free number → Regulatory Information) to confirm the verification appears and shows your ISV identity.
  • Once Twilio returns TWILIO_APPROVED (mapped to approved), sendBusinessSms() unblocks that business's outbound texts automatically.
5Roll out to clients

Each client fills the same tab; each gets its own TFV on its own subaccount number. Approval is typically 2–3 business days.

5 · One thing to confirm with Twilio (ISV scaling nuance)

Your code attaches a single TWILIO_TFV_CUSTOMER_PROFILE_SID to every business's submission. That works if Twilio treats it as your ISV/reseller profile and reads each end-business identity from the inline business* fields (which your code sends). At higher volume, Twilio's ISV model sometimes prefers a separate / secondary Customer Profile per end business. If you start seeing rejections that mention the ISV/reseller, ask Twilio support (or your account manager) whether you should create per-business profiles. One test submission (Step 4) tells you quickly.

Watch for these Twilio errors
  • 30494 — "ISV or reseller name must be provided": profile business identity isn't set to ISV/Reseller, or the ISV details are missing.
  • Approved Profile is Required — your Trust Hub Primary Customer Profile isn't approved yet.
  • Rejections citing opt-in or website — the client's opt-in proof URL or privacy/terms pages are missing or unreachable.

6 · Security note (important)

Rotate exposed secrets

Your .env.local contains live production secrets in plaintext — Twilio Auth Token, Paddle live API key, OpenAI key, Clerk secret, and others. It is correctly gitignored (.gitignore:34 → .env*), but since these values have been shared outside your machine, treat them as compromised.

  • Rotate the Twilio Auth Token (Console → Account → API keys & tokens) and update Vercel. A leaked token lets someone hijack your whole account and every subaccount.
  • Rotate the Paddle live API key and webhook secret.
  • Consider using Twilio API Keys (scoped keys) instead of the account Auth Token for the master client.

7 · How to test end-to-end

  1. Set the two env vars, redeploy (so process.env picks them up).
  2. Open /dashboard/settings?focus=sms for a test business.
  3. Submit the form; confirm the response status is pending (not error).
  4. Check Twilio Console → Trust Hub → Registrations for the new verification and its ISV identity.
  5. After approval, trigger an SMS feature (e.g. an appointment reminder) and confirm a message sid is returned — that proves sendBusinessSms() passed the gate.
Summary

Code side: ready. Twilio side: (1) upgrade + business-verify the master account, (2) create & get an approved ISV Primary Customer Profile in Trust Hub, (3) set TWILIO_TFV_CUSTOMER_PROFILE_SID and TWILIO_WEBHOOK_BASE_URL. Then every client's Business SMS submission can register and unlock their texting.
